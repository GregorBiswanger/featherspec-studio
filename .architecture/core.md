# Map: src/core (framework-free core)
# last reconciled: 2026-11-24 (0035, PD-112)

## Internal pattern
- `src/core/<area>/` — one folder per spec; `<area>Service.ts` is the application service where the
  area has one; `testing/` holds that area's worlds and fakes (imported by tests only).
- `src/core/ports/<topic>.ts` — every port the core uses; adapters implement them.
- `src/shared/protocol/` (moved from the `AGENTS.md` shared line, 2026-11-21) — the views and texts core and webview share: areas, board, Overview, next step, step guides and tips, step look, percentages, plan view, assistant view and send, detail picture, state look, side panel layout, UI texts; `vocabulary.ts` the host vocabulary (`HostKind`, `TERM_PAIRS`, `translateTerms`, `JETBRAINS_TEXTS`; 0034 T-014); `testing/` samples.
- Areas and what they hold (moved from the `AGENTS.md` snapshot, 2026-11-17):
  - `ports` — read-only file system, spec source, file watch; host ports (status bar, output, state,
    UI, folders, marker watch, clock); runtime medium; shell (trust, UI memory, actions, model
    source); board (editor, clipboard); copyNextStep (status entry, step quick pick, Copy feedback; 0017); setting; assistant (`CommandPort { execute }`, `AssistantHostPort`: extension, activate, commands, extension changes; 0024);
    setup (release archive, release HTTP, setup target, setup UI).
  - `discovery` (0001) — project verdicts, version line, active-project state, report model, controller, rerun scheduler; 0029: `setupSign.ts` (`readSetupSign`, pure) reads FeatherSpec's sign that `/sdd-setup` has not run from `AGENTS.md` and `.memory-bank/projectbrief.md` (the brief joins the marker watch paths); the sign travels as `setupRun` on the discovered folder, the repository project and the model.
  - `specs` (0002) — spec repository: file listing, spec and plan parsers, joins, diagnostics, live repository; every diagnostic carries a tier, problem or note (0016), set where it is emitted; compatibility findings are not emitted.
  - `assistant` (0024) — `assistants.ts` is the only home of the VS Code chat command strings (extension ID and the calls per assistant and target, PD-074); a host passes its own `AssistantTable` rows (`terminal` or not, targets, text builder, `timeoutMs`; JetBrains: `src/hosts/embedded/assistants.ts`, 0035, PD-112); `references.ts` holds the pure `cliText(line, paths, form)` with `CLI_FORMS`, `claudeText` is its `slash` form; `offer.ts` turns the setting value and the installed extensions into an `Offer` (none, Copilot, Claude Code); `welcome.ts` (0029) builds the welcome of the Overview and the Board while setup has not run and no spec exists; `sendView.ts` gives the detail and the first Now row their `SendView` (default target: the new chat for every step, 0026) and the closing tip sentence; `attachment.ts` (0027) holds `STEP_ATTACHES` (which steps attach), `attachmentOf` (the case and `attachesSpec` of the assistant decide whether a view carries the spec, in every version, PD-091) and `createAttachmentCheck` (a spec entry of the current model whose file exists, `stat` only; a send request may name a spec path and its plan path, and the host attaches only a spec or plan entry of the current model whose file exists, 0027, 0033); `send.ts` runs one Send with the row's timeout (5 s default) and the fallback (copy, one warning, one Output line), and a `copyFor` row (copy, then `host.execute('featherspec.openChat')`, nothing typed), attaches after the check, and begins and commits a hand-over; `handOver.ts` (0030) is the `/sdd-clarify` hand-over memory, per project root on workspace state, pruned on write; `testing/` holds `fakeAssistantHost` and `fakeOffer`. `settings/openSettings.ts` opens the Settings UI at this extension.
  - `settings` (0021) — `parseStepTipSettings` reads `featherspec-studio.showStepTips` and `featherspec-studio.modelHints` (anything else is the default; a hint over 40 characters is cut to 39 and `…`, trailing space trimmed first); `createSettingsSource(ports, parse)` pairs the read-only `SettingPort`s with a change event; the board and Overview services read it per view and recompute on a change, so the detail and the first Now row follow a setting within 500 ms in every window; `testing/fakeTips.ts` is the fake.
  - `lifecycle` (0003) — state derivation, readiness, contradictions, blocking conditions, plan in
    use, verification status, flow marker, status history, lifecycle service; `problemSentence.ts` turns a Problem into its user sentence (0022).
  - `runtime` (0004) — runtime store narrowed to the spec status history: writer lock, retention (90 days), store state; earlier run data removal.
  - `shell` (0005) — panel states and precedence, selection, remembered area, navigation request,
    spec tree, tree service, tree actions (0020; 0025: `Show in Plan Map`), the one-shot focus of a step or ways target (`shellEvent`, `panelReady`), tree label budget (`treeLabel.ts`) and the remembered side panel width (`sidePanelWidth.ts`, 0022), message router, shell service.
  - `overview` (0006, 0018) — Now and Up next rows, problems, figures and progress, activity,
    overview service (the open state of Activity lives here, reset with the last listener). 0026: Now shows at most five rows (Review oldest first by `lastChangeOf`), then `+ n more` with the set `Now`.
  - `board` (0007) — Board and spec detail view models (0025: `stepLinks.ts` names the plan step an intent or short form links to): cards, progress, narrow columns and Done memory, card date (0018), filters
    and sorting, board UI state, open-file guard, the detail's situation picture (header, next step, problems, progress with lines, files, notes, history; `detail.ts`, `situation.ts`, `shortTitle.ts`; 0019), `clarified.ts:clarifiedOf` (0030 §6.2: a changed spec after a hand-over of `/sdd-clarify` makes NS-10; `createModelSource` puts `handOvers` on the model), next step (NS rules, 0015; step view and short form, 0017), needs of a Backlog spec (0016), copy line, board service; `STEP_GUIDES` cases and intents in `nextStep.ts` and `stepTips.ts` compose the coach line and the four paragraphs of About this step from the case, the two settings and the shared texts (0021).
  - `planMap` (0023) — `planOf` turns a spec's plan into stages with step and return states, the `‖` groups and the current stage's ways, the returned-work statement (`returnedWork.ts`), card rows and the card's Copy line (three stage prompts, start lines); `planSpecs.ts` lists the specs with a plan for the Plan map; one view serves the Plan section and the Plan map. NS-6 returned work (0023) lives in `board/nextStep.ts`.
  - `copyNextStep` (0017) — current spec, project line, status entry view (text, tooltip, accessible text), Copy Next Step behaviour (click and command), quick pick items; `testing/` holds the entry world.
  - `setup` (0014) — the only writer and network user: release download and check, file classes, `.gitignore` and
    `settings.json` completions, apply, merge prompt, setup service; `testing/` holds the in-memory target and scripted HTTP.
