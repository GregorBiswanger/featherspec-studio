## Decisions taken on `/sdd-clarify` findings — foundation specs 0001–0004 (2026-11-16, proxy)

Cross-spec rules first; they bind every spec that touches the topic.

| ID | Topic | Decision |
| --- | --- | --- |
| PD-018 | Spec identity | A spec **entry** is one file and is keyed by its project-relative path (always unique). The **stem** `NNNN-slug` is the join key to plans, archived plans and return notes and the stable reference for consumers while it is unique. A move between lifecycle folders keeps the stem (same spec, new path). A stem change is "removed + new". The four-digit number is a display ID only |
| PD-019 | Duplicates | Same stem in two folders, or one number with two slugs: every file stays its own entry and its own card, each with a duplicate diagnostic. Nothing picks a canonical copy. A duplicated entry is never Ready. (Replaces 0003 A-001) |
| PD-020 | Who detects what | 0002 reports file facts and parse diagnostics only: unreadable file, unknown values, duplicates, orphan plan, dangling link, unverified version. Lifecycle contradictions (folder × spec status × plan status, missing archive link on a `done/` spec) belong to 0003 alone |
| PD-021 | Board-state precedence (0003) | First match wins: (1) folder `done/` → Done, whatever the status; a status other than Implemented/Baseline/Deprecated adds a contradiction diagnostic. (2) plan `Blocked` or a `BLOCKED` return note → Blocked, also for contradictory specs. (3) contradictory or unreadable spec → placed by its folder (backlog → Backlog, active → Active), never Ready or Review. (4) Review. (5) Active. (6) Ready. (7) Backlog |
| PD-022 | Deprecated successor | Read from the spec if the documented link or the text `successor: none — behaviour removed` is present; otherwise "successor: not available". The shape is UNVERIFIED (no real sample): covered by a synthetic fixture and flagged as such |
| PD-023 | Status history baseline | The history is an observation log, best effort. Whenever no earlier entry for a spec exists (first run, pruned, cleared, unreadable store) the cause is *first observed* and there is no old state. Changes that happened while the store was unavailable are not recorded later. Keyed by stem |
| PD-024 | Restart and resume | No "recovery pending" state. At activation every stored run in an open state becomes `Interrupted` (cause: extension host restarted). Resuming an `Interrupted` run is a later, explicit user action owned by 0011 and offered only where the provider declares resume (PD-007) |
| PD-025 | Ownership of run vocabulary | 0004 owns what is stored: the eight run statuses of handoff FR-011.2 as a closed list, and an event envelope whose `type` is an open string. 0009 defines the event taxonomy on top, 0011 the allowed transitions. 0004 depends on 0001 only — no dependency on 0009 or 0011 |
| PD-026 | What "this project's history" means | Runtime data are keyed by the active project's root-folder URI as 0001 reports it. One store per project root. A different project placed at the same path inherits the old history — accepted and documented as a limitation |
| PD-027 | Retention (confirms PD-012 against ADR-002) | Age cap 90 days by default, configurable; command "FeatherSpec Studio: Clear Run History" with a confirmation every time. ADR-002's "last 50 runs / 30 days" is superseded by this. A per-run size cap with a "truncated" marker event stays as ADR-002 proposes; data kept aside as unreadable is removed by the same command |
| PD-028 | Unreadable runtime data | Granularity is the run. An incomplete last record (process killed mid-write) is skipped on read and reported once; the file is append-only and never rewritten. Any other unreadable part marks that one run "history unreadable", its files stay untouched, other runs are unaffected. If the index is unreadable it is rebuilt from the per-run files |
| PD-029 | Secrets in runtime data | Studio masks before storing: (a) the values of credentials it holds itself, supplied by the adapters through a port; (b) the pattern list kept in the repository under `docs/security/secret-patterns.md` (provider tokens, bearer tokens, private-key blocks). Studio does not read `.env` files. Masking is best effort and documented as such; raw provider data are not stored in the MVP |
| PD-030 | Second window | One writer per project store, enforced by a lock with a heartbeat. A second window on the same project reads runtime data, cannot start runs and never changes run statuses; it says why. A stale lock is taken over |
| PD-031 | Project verdicts (0001) | Three verdicts: *project*, *incomplete*, *not a project*. Markers: M1 = root `AGENTS.md` with a `FeatherSpecVersion:` line, M2 = root `.specs/` directory. Both → project. `AGENTS.md` without the line + `.specs/` + `.claude/commands/sdd-*.md` → project with the attribute *legacy*, version "unknown", diagnostic recommending `/sdd-featherspec-update`; it counts as a project everywhere. Exactly one of M1/M2 → incomplete, cannot become active. The `.github/copilot-instructions.md` location is out of scope until a real sample exists |
| PD-032 | Version line (0001) | The first line of `AGENTS.md` matching `FeatherSpecVersion:` followed by a value, wherever it stands; the value is the first token, a trailing `# comment` is ignored, shown as written. Empty value → "unknown" plus diagnostic. A second such line → first wins plus diagnostic |
| PD-033 | Active project (0001) | The active project is always remembered, also when it became active without asking. A remembered project that disappears keeps its "not found" message until the user selects another one or it returns; if it returns and nothing else was selected, it is active again. Discovery reruns when a workspace folder is added or removed and when root `AGENTS.md` or root `.specs/` appears, changes or disappears — not on changes inside `.specs/`. No status bar entry and no message in a workspace where no folder is a project or incomplete |
| PD-034 | Reading criteria and requirements (0002) | An acceptance criterion is defined where an `AC-NNN` ID is the leading token of a list item or bold paragraph, anywhere in the file. *Uncertain* is decided by the `[Uncertain]` marker only. `FR-` IDs are read the same way (leading token or first table cell). The body is exposed as ordered sections (heading text + raw content); no section is identified by its meaning. A `**Plan:**` link to a missing file is always a diagnostic; the only link that may dangle is an archived plan's `**Spec:**` line |
| PD-035 | Thresholds (0002, 0006, 0007) | Working thresholds, mine, to be re-measured on a real project: full read of a generated 200-spec fixture under 2 s; model updated within 1 s after the file-change event reaches Studio. Measured by an automated test on the fixture; a failed re-measurement reopens the spec |
